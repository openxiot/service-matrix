环境变量

点号配置在部署侧怎么写、哪些开关只能开在一个副本、开完看哪行日志。能源采样与 Modbus 轮询共用同一条约定：开关缺省关，由 poller 副本打开。

变量格式
属性名大写，非字母数字换下划线
缺省行为
采集类开关全部关闭
生效方式
新 revision / 重启进程

01命名与优先级

点号属性怎么变成环境变量

代码里用 MicroProfile Config 读取配置，属性名是点号形式；部署侧的环境变量名由同一个名字推导：全部大写，每个非字母数字字符换成下划线。

application.properties环境变量
energy.sample.enabledENERGY_SAMPLE_ENABLED
energy.sample.interval-secondsENERGY_SAMPLE_INTERVAL_SECONDS
energy.sample.zoneENERGY_SAMPLE_ZONE
modbus.poll.enabledMODBUS_POLL_ENABLED
modbus.poll.invoke-timeout-secondsMODBUS_POLL_INVOKE_TIMEOUT_SECONDS
modbus.history.retention-daysMODBUS_HISTORY_RETENTION_DAYS
  • 环境变量优先于 application.properties，文件里的值优先于代码里的 defaultValue。
  • 布尔值写小写 true / false；数值不带单位，秒就是秒。
  • 带点的变量名（energy.sample.enabled）不会生效，容器平台通常也不接受这种名字。写成 ENERGY_SAMPLE_ENABLED。
  • 这些开关都在启动时读取，改完要产生新 revision 或重启进程，热改无效。
为什么用环境变量而不是写进文件

同一个镜像要部署成两种角色：面向用户的 api 副本，和只负责采集的 poller 副本。采集开关写进 application.properties 会让所有副本一起开，这正是下面要避免的事。

02副本分工

同一个 jar，两种角色

service-matrix 的部署约定是 api N 副本 + poller 1 副本。镜像相同，靠环境变量区分职责。采集类开关的缺省值都是 false；没有显式打开的副本只提供 HTTP 接口。

api 副本

HTTP / 报表 / 状态

  • MODBUS_POLL_ENABLED 不设
  • ENERGY_SAMPLE_ENABLED 不设

poller 副本

采集 / 轮询 / 采样

  • MODBUS_POLL_ENABLED=true
  • ENERGY_SAMPLE_ENABLED=true
为什么只能一个
能源采样按点位基线累加增量：两个副本各读一次、各写一次 $inc，同一段电量会被记两遍。Modbus 轮询则会让同一条 RS485 总线上出现重复帧。
采样器不发帧
能源采样读的是库里的影子：服务点位读设备影子，寄存器点位读 Modbus 影子。它和 poller 放一起只是运维上的约定，不是协议要求；但 register 点位的值依赖 poller 更新影子。
索引不受影响
各模块的 *.index.enabled 缺省为 true，每个副本启动时都会幂等地建索引，多副本重复执行无害。

03能源采样

打开之后从当下开始累计

能源采样的四个变量都在 EnergySampler 里读取。除了开关，其余三项一般保持缺省，只有时区建议显式指定。

环境变量缺省说明
ENERGY_SAMPLE_ENABLED false 调度开关。只在一个副本上设 true，通常就是 poller。
ENERGY_SAMPLE_INTERVAL_SECONDS 60 采样周期；小于 10 会被夹到 10。
ENERGY_SAMPLE_ZONE system 小时桶的边界时区。system 跟随容器时区，建议显式写 Asia/Shanghai。
ENERGY_INDEX_ENABLED true 启动时建 energy-configs / energy-stats 索引；测试进程设 false。 
# 只配在 poller 副本上
ENERGY_SAMPLE_ENABLED=true
ENERGY_SAMPLE_ZONE=Asia/Shanghai
# 可选：采样周期，秒
ENERGY_SAMPLE_INTERVAL_SECONDS=60
没有补历史

每个点位的第一条读数只用来建立基线，不产生增量。因此开关打开之前的时段不会凭空出现数据，报表里会是空桶；需要历史只能等它从现在开始积累。

打开开关后，启动日志里会出现两行：

energy indexes ensured
energy sampler started, interval=60s

04Modbus 轮询

poller 副本的七个旋钮

轮询器有自己的开关和一组调度参数，缺省值都在代码里；application.properties 只作说明，不设 enabled。

环境变量缺省说明
MODBUS_POLL_ENABLEDfalse调度开关，只在一个副本上设 true。
MODBUS_POLL_CONCURRENCY20同时采集的设备上限。
MODBUS_POLL_WAKEUP_MILLIS1000唤醒周期，也就是到点任务的最大延迟。
MODBUS_POLL_RECONCILE_SECONDS300周期对账间隔；定义变更最迟这么久生效。
MODBUS_POLL_JITTER_PERCENT10周期抖动，防止整点齐发。
MODBUS_POLL_INVOKE_TIMEOUT_SECONDS10单次采集超时，必须小于 lease。
MODBUS_POLL_LEASE_SECONDS60任务租约；扩容时保证同一任务只有一个副本在跑。

超时大于等于租约时，一次慢应答会拖到租约过期，另一个副本会把同一条任务抢走重发。两个值要一起调，保持超时明显小于租约。

05历史与索引

缺省就生效的那几个

下面这些参数与采集开关无关：只在 poller 上需要，但它们的缺省值已经会改变数据保留行为，值得在部署前确认。

环境变量缺省影响
MODBUS_HISTORY_DEADBAND0数值死区，0 = 精确比较；仅对数值生效。
MODBUS_HISTORY_KEEP_ALIVE_SECONDS600值没变也强制落一条；≤ 0 关闭。
MODBUS_HISTORY_RETENTION_DAYS90不设也已经生效：在 at 上建 TTL 索引，后台删 90 天前的明细。设 0 或负数会关闭并删除已有 TTL 索引。

索引开关

五个 *.index.enabled 缺省都是 true，测试进程在 src/test/resources/application.properties 里全部关掉。

环境变量建什么
SPACE_INDEX_ENABLED空间树 ancestors 索引
DASHBOARD_INDEX_ENABLED看板布局 spaceId 唯一索引
CARD_INDEX_ENABLED卡片配置的 spaceId 索引，并清理旧唯一索引
MODBUS_INDEX_ENABLEDModbus 点表索引
ENERGY_INDEX_ENABLED能源配置与小时桶索引

07配置示例

staging 上的两条命令

api 与 poller 是两个 container app 时，只给 poller 设采集开关。改环境变量会生成新 revision 并重启。

# poller：打开轮询与能源采样
az containerapp update \
  --name <poller-app> --resource-group staging \
  --set-env-vars \
    MODBUS_POLL_ENABLED=true \
    ENERGY_SAMPLE_ENABLED=true \
    ENERGY_SAMPLE_ZONE=Asia/Shanghai

# api：确保没设这两个开关（缺省即 false）
az containerapp update \
  --name service-matrix --resource-group staging \
  --remove-env-vars MODBUS_POLL_ENABLED ENERGY_SAMPLE_ENABLED

本地或 docker 运行同理：

docker run --rm -p 8080:8080 \
  -e QUARKUS_MONGODB_CONNECTION_STRING='mongodb://host:27017/matrix' \
  -e ENERGY_SAMPLE_ENABLED=true \
  -e ENERGY_SAMPLE_ZONE=Asia/Shanghai \
  ghcr.io/openxiot/service-matrix:latest

08验证与排错

看日志，不看猜测

启动后按副本核对这几行，就能确认开关是否真的读到。

副本期望日志
pollermodbus poll enabled, instance=…, concurrency=…, wakeup=…ms, timeout=…s, lease=…s
pollerenergy sampler started, interval=60s
pollerenergy indexes ensured
apimodbus poll disabled
api没有 energy sampler started
配了却没生效
先看变量名：写成 energy.sample.enabled 或 Energy.Sample.Enabled 都不会被读到。再确认改的是容器 app 的 env，而不是本地 shell。
数据翻倍
两个副本都开了能源采样，或者两个 poller 都在跑。检查每个副本的 ENERGY_SAMPLE_ENABLED，保留一个。
小时桶错位
ENERGY_SAMPLE_ZONE 没设或容器时区不是 UTC+8。已写入的小时桶不会跟着改，换时区只影响之后的数据。
报表没有历史
刚打开开关时是正常的：第一条读数只建基线，不产生增量，数据从打开之后开始积累。
